ClinicaOS · organização do time

Divisão do sistema em 3 frentes de trabalho

Proposta para três colaboradores trabalharem em paralelo sem mexer no código um do outro. Cada frente é um fluxo de negócio completo, da tela ao banco, para que uma pessoa entregue uma funcionalidade inteira sem abrir arquivo de outra frente. O OS ZAP fica fora da divisão.

Base: main no commit ac6bc6cc (10/10/2026). Levantamento feito no código: pastas, rotas, imports entre arquivos, 912 migrations e histórico git dos últimos 60 dias.

Regras de trabalho com Git e Lovable

  1. Nada direto na main. Cada tarefa vai em uma branch com o prefixo da frente: f1/…, f2/…, f3/… ou nucleo/…. Entra na main só por Pull Request.
  2. CI verde antes do merge. O PR roda Lint, Typecheck e Testes. Localmente: npm run lint, npm run typecheck, npm run test.
  3. PR pequeno e de uma frente só. Se tocar arquivo de outra frente ou do núcleo, marque o dono para revisar.
  4. Arquivos gerados não se resolvem à mão. Em conflito no routeTree.gen.ts ou no supabase/types.ts, aceite qualquer lado e gere de novo.
  5. Menu e permissões são os maiores pontos de conflito. Em 60 dias, app-shell.tsx mudou 120 vezes e as listas de permissões 46. Cada frente só edita o bloco do seu grupo de menu e das suas rotas, sem reordenar o resto.
  6. Feature flags por clínica continuam valendo. Melhorias entram atrás de flag, e o módulo clássico só sai quando a V2 for promovida.
  7. Avise antes de mexer em tabela compartilhada ou no núcleo, no canal do time. No fim do dia, cada um faz push da sua branch.

O Lovable é o maior risco de interferência. Nos últimos 60 dias, 5.113 commits na main vieram do bot do Lovable, que grava direto na main e não conhece as fronteiras. Todo prompt deve dizer a frente e listar as pastas que não podem ser tocadas. Antes de usar o Lovable, faça git pull; depois, confira o diff. De preferência, só uma pessoa usa o Lovable por vez.
